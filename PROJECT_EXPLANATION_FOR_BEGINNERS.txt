STUDY NOTION PROJECT EXPLANATION (BEGINNER FRIENDLY)

1) WHAT IS THIS PROJECT?
Study Notion is an EdTech web application built with the MERN stack.
Think of it as an online learning platform where:
- Students can sign up, explore courses, buy courses, and learn.
- Instructors can create and manage courses.
- Admin can manage platform-level things like categories.

In simple words: this is a full learning marketplace + learning management system.


2) WHAT PROBLEM DOES IT SOLVE?
This project solves common online education problems:
- Learners need one place to discover and study courses.
- Instructors need tools to publish and manage courses.
- Platforms need secure login, role-based access, payment flow, and progress tracking.

Without such a system, everything is fragmented: one tool for content, another for payments, another for progress.
Study Notion combines all these in one product.


3) MAIN USERS AND THEIR ROLES
A) Student
- Signs up/logs in
- Browses courses and categories
- Enrolls/pays for courses
- Watches course content
- Tracks progress
- Leaves ratings/reviews

B) Instructor
- Creates and edits courses
- Manages sections and subsections (course structure)
- Views instructor dashboard data (students/revenue)

C) Admin
- Manages categories and platform-level controls


4) CORE FEATURES
- Authentication with OTP and JWT
- Role-based authorization (Student, Instructor, Admin)
- Course creation/editing/deletion
- Section and subsection management
- Course catalog and search

6) HIGH-LEVEL ARCHITECTURE
This project follows a layered architecture:

Layer 1: Frontend (React app)
- Renders pages/components
- Captures user actions
- Calls backend APIs
- Stores session/UI state in Redux

Layer 2: Backend API (Express app)
- Receives requests from frontend
- Validates auth + roles with middleware
- Runs business logic in controllers
- Talks to database models
- Sends JSON responses

Layer 3: Data Layer (MongoDB via Mongoose)
- Stores users, profiles, courses, categories, ratings, progress, etc.

This separation makes the app easier to maintain and scale.


7) FOLDER STRUCTURE EXPLANATION
ROOT
- package.json: frontend scripts and dependencies
- README.md: project overview and setup

/public
- index.html and static files
- service worker and install prompt logic

/src (Frontend)
- pages/: screen-level routes (Home, Login, Signup, Dashboard, etc.)
- Components/: reusable and feature-specific components
- services/: API connectors and endpoint definitions
- slices/: Redux slices (auth, profile, cart, loading, etc.)

/server (Backend)
- index.js: backend entry point
- routes/: API endpoints grouped by domain
- controllers/: business logic handlers
- models/: mongoose schemas
- middlewares/: auth/role/demo guards
- config/: DB/cloudinary/razorpay setup
- mail/: email templates
- utils/: helper functions


8) REQUEST FLOW (HOW DATA MOVES)
Generic flow:
1. User clicks a button in frontend.
2. Frontend service function calls API endpoint.
3. Express route receives request.
4. Middleware checks token/role if needed.
5. Controller validates input and applies business logic.
6. Controller reads/writes MongoDB using models.
7. Backend returns JSON response.
8. Frontend updates Redux state and UI.


9) IMPORTANT USER FLOWS
A) SIGNUP/LOGIN FLOW
- User enters credentials.
- OTP and signup/login APIs are called.
- On success, backend returns token and user data.
- Frontend stores token/user and redirects to dashboard.

B) COURSE CREATION FLOW (INSTRUCTOR)
- Instructor opens dashboard and course form.
- Submits details -> createCourse API.
- Backend verifies instructor role.
- Course record is created and linked with category/instructor.

C) PURCHASE FLOW (STUDENT)
- Student chooses a course and starts payment.
- Backend creates Razorpay order.
- Payment verification endpoint confirms transaction.
- Enrollment is applied and success email can be sent.

D) LEARNING + PROGRESS FLOW
- Student opens enrolled course content.
- Completes lectures/subsections.
- Progress update API stores completion data.


10) WHY THIS PROJECT IS GOOD FOR LEARNING
